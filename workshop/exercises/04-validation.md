# Exercise 4 (7 min): Add a practical validation step

## Objective
Add a lightweight, practical validation step even when full test infra may be absent.

## Do this
1. Perform a manual content validation on `/workshop/starter/app.js`:
   - Confirm every visible section renders fictional content only.
   - Confirm there are no hardcoded secrets or personal data.
2. Optional if local runtime is available: open `/workshop/starter/index.html` in a browser and verify the page renders.
3. Record validation notes in `/workshop/references/example-solution.md` under a "Validation Notes" heading.

## Expected outcome
You have a documented validation pass that matches repository quality expectations.

## Acceptance criteria
- [ ] Validation notes were added.
- [ ] Notes mention security/content checks.
- [ ] Optional runtime step is clearly marked optional.

## Reflection checkpoint
Why is documenting validation useful when automated tests are limited or unavailable?
